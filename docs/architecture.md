# Architecture

## One source, multiple projections

```text
generated orientation docket
  -> human orientation and semantic record candidate
  -> brain manifest candidate
  -> operating policy + closed type kernel
  -> deterministic bootstrap plan
  -> portable workspace bundle
  -> host adapter projection
  -> human review
  -> exact local installation confirmation
  -> ownership manifest and receipt
  -> separately released host activation or runtime effect
```

The portable brain manifest owns the user's selected roles, workspace location, governance invariants, and held effects. It does not own source content, accepted meaning, human decisions, or host configuration.

The bootstrap compiler is deliberately smaller than an agent runtime. It validates selections, computes a stable plan ID, and renders proposed bytes in memory. The separate lifecycle layer may write those reviewed bytes to a clean local target and record its exact ownership. It does not call a model, inspect credentials, activate an adapter, or choose a provider.

## Workspace topology

The proposed starter topology uses eight ordinary directories:

- `sources/` for original or externally owned material;
- `knowledge/` for reviewed knowledge records and maps;
- `projects/` for bounded active project surfaces;
- `workflows/` for candidate procedures and graphs;
- `decisions/` for human dispositions and rationale records;
- `evidence/` for observations, tests, counterevidence, and uncertainty;
- `receipts/` for bounded transformation and runtime history;
- `archive/` for preserved inactive or superseded material.

The power-of-two count is a starter capacity choice, not a claim that knowledge naturally has eight categories. A user may adapt the topology after reviewing ownership and migration consequences.

## RFC-style instruction model

The root `AGENTS.md` is a detailed extended-mind constitution with stable `AKOS-RFC-0001.x` clauses: shared law expressed with normative terms, precedence, semantic orientation, type boundaries, delegation envelopes, source classes, knowledge routes, independent effect gates, amendment, and completion rules. More specific directories may add narrower local instructions when a real consumer and validation need exist. Host adapters may project this contract but cannot weaken it or silently write back.

Core8 profiles are advisory partial transformations. Each selected role has a portable instruction file containing its first attention signal, routing question, admission test, typed domain and codomain, invariants, failure returns, owned outcome, non-triggers, falsifier, boundaries, and handoff contract. Their declarations constrain outputs and prohibited effects; they do not grant tools, permissions, provider access, filesystem scope, or authority over the user.

## Operational Intelligence

Operational Intelligence is a comparison and compilation lens. It can identify source drift, missing ownership, invalid transitions, unresolved gates, stale context, and return readiness. It cannot select a profile, decide truth, infer personal meaning, or authorize an effect.
