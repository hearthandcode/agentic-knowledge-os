# Core8 orientation

## Core idea

Core8 is a functional compression of a much broader governed capability space. It is not eight personalities, eight always-on agents, or a popularity-ranked subset of a larger fleet. Each role exists because it owns one recurring transformation in the life of an extended mind and exposes a clean boundary to the next transformation.

The compression criterion is operational completeness: together, the roles can orient, select context, examine evidence, shape meaning, compile contracts, build a candidate, review it independently, and preserve continuity. The number eight is a bounded starter distribution; it is not a claim that every person's cognition or knowledge naturally divides into eight parts.

## Role orientation

| Role | First attention signal | Owned outcome | Hard boundary |
| --- | --- | --- | --- |
| Coordinator | Route, ownership, or return state is unclear | Bounded route and attributed sequence | Cannot centralize meaning or grant authority |
| Context Curator | Source load, freshness, sensitivity, or context budget matters | Minimal context pack with omissions and refresh rules | Cannot infer missing sources or broaden access |
| Evidence Analyst | Claims need provenance, counterevidence, uncertainty, or falsifiers | Epistemic claim ledger | Cannot decide truth or acceptance by confidence |
| Knowledge Architect | Meaning, ownership, navigation, or lifecycle structure is unclear | Source-bound knowledge architecture | Cannot create categories without a consumer or own another person's meaning |
| Knowledge Engineer | A design needs machine-readable precision | Closed, loss-visible transformation contract | Cannot disguise unresolved semantics as schema validity |
| Builder | A released design is ready for implementation | Bounded candidate plus direct check evidence | Cannot implement unreleased scope or touch unowned paths |
| Reviewer | A candidate needs criteria-based independent examination | Evidence-linked disposition candidate | Cannot edit the candidate or accept for the human owner |
| Steward | Privacy, retention, recovery, archive, or deletion is implicated | Lifecycle handoff with lineage and recovery | Cannot broaden disclosure or infer deletion authority |

## A role is a partial transformation

Each profile declares:

- an attention signal and first routing question;
- an admission test;
- a typed domain and codomain;
- preconditions and invariants;
- named failure returns;
- four public RFC rules with conditions, requirement levels, failure returns, and evidence checks;
- one owned outcome;
- non-triggers and non-owner boundaries;
- a falsifier;
- allowed handoff targets;
- a return contract.

This makes role selection inspectable. A role runs only when its admission test is satisfied. If the source, owner, scope, type, or gate is absent, the role returns a diagnostic or bounded hold instead of producing a plausible substitute.

The shared contract procedure is `orient -> select-profile -> admit-inputs -> apply-rules -> transform -> validate-outputs -> check-effects -> return`. The return names the input and output type references, every applied rule ID, failed guards, performed and unperformed effects, and the next human decision. Unknown input or rule state holds with a diagnostic.

Select the primary role by the requested terminal artifact. Default to no handoffs; include only necessary transformations or a future sequence expressly requested in a plan. Optional consultation stays separate. A completed report may describe an unresolved subject, and a completed proposal may await later acceptance. Supply the actual requested artifact content and request a human decision only when a human choice blocks that requested outcome. In-response reporting is an output; consequential filesystem, runtime, external and semantic-acceptance transitions are effects.

These clarifications were exercised in the [v6 remediation evaluation](evaluation-result-v6.md). Full AKOS passed 13 of 24 governed trials and did not meet the qualification threshold. The result motivates further consumer-shape and source-identity work; it does not establish the fleet's effectiveness.

## Semantic orientation across Core8

Semantic authority stays at L1 with the person or named source owner. The fleet may preserve literal material, propose normalized vocabulary, build hypotheses, compare interpretations, and produce an ontology candidate. It may not silently turn any of these into accepted meaning.

The six modes are:

- `literal`: preserve or retrieve without semantic expansion;
- `minimal`: default, two to four useful dimensions plus one boundary;
- `balanced`: four to eight dimensions with omissions and uncertainty;
- `contrastive`: compare alternatives and disconfirming evidence;
- `expansive`: only after an explicit human request and still bounded;
- `no-expansion`: exact-source or sensitive work with diagnostics only.

The mode belongs to the task, not the user's identity. It does not establish a stable personal preference.

## Boundaries between the roles

The most important seams are deliberate:

- Context Curator selects sources; Evidence Analyst evaluates what they support.
- Evidence Analyst models epistemic status; Knowledge Architect models the domain structure.
- Knowledge Architect establishes semantic distinctions; Knowledge Engineer compiles them into schemas and transformations.
- Knowledge Engineer specifies; Builder implements only released scope.
- Builder produces evidence; Reviewer independently interprets it against criteria.
- Steward owns continuity and privacy boundaries, but not semantic acceptance.
- Coordinator composes handoffs; it does not become a super-role.

These separations are safeguards against a single fluent agent silently moving from interpretation to implementation to self-approval.

The same seams are adversarial boundaries. Embedded source instructions cannot broaden context access; undeclared fields cannot smuggle defaults into a schema; a design proposal cannot impersonate accepted implementation scope; and a reviewer cannot turn authorship into permission to self-approve.

## Public-source relationship

This distribution uses original wording and a deliberately lossy abstraction of governed profile-contract patterns. It does not distribute private profile bodies, personal context, internal paths, or unpublished operational records. The public Core8 is therefore a new portable contract, not a claim of byte lineage or equivalent runtime behavior.
