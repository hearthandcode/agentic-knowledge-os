# Refined design plan

## Goal

Refine Agentic Knowledge OS from a fleet-and-folder bootstrap into a small, inspectable operating constitution for a user-owned extended mind. The design must surface semantic orientation, operational intelligence, and governance without copying a private profile corpus or claiming that an internal source package has been publicly released.

## Selected synthesis profile

- Profile: `source-grounded-synthesis`
- Method: semantic orientation plus knowledge/provenance engineering
- Artifact class: public source candidate
- Review state: review-required
- Verified: false

## Source relationship

The design is an original public adaptation of abstract operating patterns observed in a larger governed profile system. It preserves the distinction between source, interpretation, projection, and effect. Exact private profile bodies, private context, internal paths, and unpublished source excerpts remain excluded.

## Design decision

Core8 is a functional compression, not a smaller cast of autonomous personas. Each profile owns one bounded transformation with a declared domain, codomain, admission test, invariants, failure return, falsifier, and handoff seam. No profile owns the user, truth, semantic acceptance, or an external effect.

The portable system has three layers:

1. Semantic layer: preserve literal material, proposed normalization, hypotheses, uncertainty, and human-accepted meaning as distinct states.
2. Operational layer: express work as typed records, guarded transitions, evidence, projections, and return envelopes.
3. Host layer: project the portable contract into Hermes, Pi, a neutral harness, or a future accepted Exocore interface while retaining loss and no-write-back.

## Implementation slice

- enrich the public Core8 registry with role-owned typed transformations;
- add a closed shared type kernel and machine-readable operating policy;
- add a generated first-run orientation docket;
- revise the generated `AGENTS.md` into clause-addressable local RFC law;
- revise profile projections to expose admission, non-trigger, falsifier, and handoff rules;
- update schemas, fixtures, validation, lifecycle ownership, tests, and documentation;
- retain exact plan confirmation, manifest-owned rollback, provider neutrality, and all live-host holds.

## Non-effects

This work does not install a live workspace, activate a host profile, call a provider, expose private source material, accept semantic meaning for a user, stage or publish Git state, or establish runtime efficacy.

## Checks

The source must demonstrate deterministic planning, closed profile fields, resolvable type references, clause and role uniqueness, generated-file ownership, drift-safe removal, synthetic fixtures, and public-safety scans. These checks do not establish semantic quality or human acceptance.
